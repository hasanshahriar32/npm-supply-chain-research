# Consumer evidence feasibility pilot
Frozen before inspection of consumer manifests or lockfiles on 2026-11-20 at 14:17 UTC. This is a dated repository protocol for a feasibility analysis. The earlier findings and the original graph were already known.

The unit is one sampled public self-hosted application repository. Use the 40 draws and commit cutoff in the companion acquisition protocol. Preserve every sampled row including failed requests. For this pilot support the root npm importer with lockfileVersion 2 or 3. Respect npm-shrinkwrap.json precedence. If its status is ambiguous, do not substitute package-lock.json. An explicit different package manager or conflicting manager evidence without a clear choice is unevaluable. Missing root evidence cannot rule out a nested application.

Measure the number of projects for which a supported static production path can be traced. Compare a purpose-built parser with npm Arborist's offline virtual tree on the same bytes. Follow ordinary required production dependencies from the root. Exclude development, optional, peer, alias, linked/workspace, override and platform-dependent semantics outside the common supported scope. Record disagreements and limits. Neither implementation executes an install. Both use npm SemVer. Concordance indicates agreement on the supported inputs and supplies no independent human accuracy estimate.

Secondary descriptive comparison: take exactly the existing greedy_coverage orders at 100 slots from the name and version representations in the October 100-root cohort's incidence.json (SHA-256 74184752cc97d6ff0dcec3ae8ba39847d7303a54557be982b387235202215bc8). These orders predate consumer collection. Use only exact package/version registry responses with matching identities from the same acquisition. Count a witness for a portfolio if both parsers reach the same physical package location and exact version and an observed account for that package/version is among its frozen selection. Record evidence coverage for all joined versions and each portfolio, selection overlap, and the four paired documented-hit cells, plus missing/unevaluable cases. Count old endpoint overlap. Never infer account control at the later consumer commit. Absence of a recorded witness cannot be interpreted as absence of a dependency or account. Expose unresolved joins and range of possible outcomes. Do not release rankings of individual accounts.

No effect size, direction or minimum number of evaluable projects determines which rows are retained. No replacement or tuning on the sample. If the evidence is sparse, use the measurements to scope the next study. No security-incident, execution or human-review outcome is under test.
