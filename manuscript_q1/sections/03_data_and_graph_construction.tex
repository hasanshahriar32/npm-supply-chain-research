\section{Data Corpus and Graph Construction}
\label{sec:data_construction}

To conduct our empirical investigations, we construct and analyze two distinct mathematical graph representations derived from a centralized snapshot of the npm ecosystem, enriched with continuous-integration metadata and repository links from deps.dev~\cite{depsdevapi} and GitHub.

\subsection{Study Universe and Empirical Dimensions}
The empirical corpus analyzed in this study comprises:
\begin{itemize}
    \item \textbf{Packages ($P$):} 25,228 unique npm package names.
    \item \textbf{Package Versions ($V$):} 22,340 versions possessing detailed dependency manifests.
    \item \textbf{Maintainer Accounts ($M$):} 12,217 unique publisher accounts, spanning 79,405 author-package assignments.
    \item \textbf{Dependency Edges ($E_{\text{dep}}$):} 88,113 unique directed package-to-package dependency relationships (48,705 direct dependencies, 73,180 transitive relations).
    \item \textbf{Workflow-Verified Repositories ($R_{\text{wf}}$):} 7,171 distinct client software repositories with verified, active GitHub Actions continuous-integration workflows.
\end{itemize}

\subsection{Two Graph Representations: Name-Projected vs. Version-Continuous}
A central contribution of our study is evaluating prioritization sensitivity across two structural graph models:
\begin{enumerate}
    \item \textbf{Package-Projected Graph ($G_{\text{proj}}$):} Standard in the literature, this representation collapses all published versions of package $p$ into a single node. A directed edge $(u, v) \in E_{\text{proj}}$ exists if \textit{any} version of $u$ declares a dependency on package $v$. Maintainer reach closures $\reach(m)$ are computed via transitive closure over $G_{\text{proj}}$.
    \item \textbf{Version-Continuous Graph ($G_{\text{ver}}$):} This ground-truth representation explicitly preserves discrete version nodes $v \in V$. A directed edge $(v_1, v_2) \in E_{\text{ver}}$ exists if version $v_1$ declares a SemVer constraint that resolves to version $v_2$. Reach closures $\reach_{\text{ver}}(m)$ require a valid, continuous version path from client repositories to upstream maintainer-authored releases.
\end{enumerate}

\subsection{Cycle Resolution and SCC Condensation}
Real-world package dependency graphs contain cyclic dependencies caused by circular development utilities, mutual peer dependencies, and legacy meta-packages. To ensure exact, deterministic reachability computation without infinite recursion, we apply Kosaraju's Strongly Connected Component (SCC) condensation algorithm:
\begin{itemize}
    \item In the package-projected graph, we identify \textbf{82 package nodes involved in 68 cyclic SCC components}. The largest cycle contains 4 packages (\texttt{glob}, \texttt{rimraf}, \texttt{minimatch}, \texttt{graceful-fs}).
    \item In the version-continuous graph, \textbf{68 cyclic components} are detected across 40,806 version nodes.
\end{itemize}
Each cyclic component is condensed into a single super-node with bitwise union of outgoing edges. The resulting graph is a Directed Acyclic Graph (DAG), enabling exact, linear-time topological reach propagation via 64-bit integer bitmasks.

\subsection{Dataset Hygiene, Disagreements, and Phantom Reach}
To ensure rigorous dataset hygiene, we audited parser disagreements and contextual node markers:
\begin{itemize}
    \item \textbf{Lexical URL Parser Disagreements:} We identified 658 package records where the repository URL recorded in npm metadata disagreed with lexical URL parsing (e.g., git subdirectory references, SSH vs. HTTPS schemas). We audited the sensitivity of excluding 60 positive observations with ambiguous remote mappings, reducing the repository universe from 7,171 to 7,147 ($C = 5,524, P = 799$ at budget 100), confirming that mapping discrepancies do not alter our comparative findings.
    \item \textbf{Contextual Node Invariance:} npm metadata contains 2,745 bundled-context identifiers. Removing these contextual nodes leaves primary workflow repository reach strictly invariant across all 462,170 identity--repository pairs.
    \item \textbf{Phantom Reach Witnesses:} Package-name projection introduces substantial ``phantom reach''---dependency paths that appear reachable in collapsed graphs but cannot exist under any valid SemVer installation. We verified five explicit witness packages---\texttt{pseudomap}, \texttt{is}, \texttt{foreach}, \texttt{indexof}, and \texttt{has-color}---where legacy versions link to modern frameworks, artificially inflating perceived downstream blast radius by up to 287\%.
\end{itemize}
