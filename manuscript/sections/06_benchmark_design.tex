\section{Discussion and Evaluation Requirements}
\label{sec:future}
The inconsistency affects an operational decision: choosing an archive changes 188 entries in the default 253-package review queue. Reproducibility therefore requires binding derived metrics to their source observations, not merely recording population size. Queue interfaces should expose boundary ties instead of implying a strict evidence-based order.

A future compromise benchmark should freeze its at-risk population, observation unit, cutoff, and horizon before examining outcomes. Established-package publisher compromise should be separated from malicious new publications, ordinary vulnerabilities, and protestware. Controls need comparable follow-up and documented surveillance; unresolved outcomes must remain unknown. Case--control prevalence alone cannot support population calibration.

Features require historically supported dependency resolution, maintainer/publisher semantics, repository mappings, workflow configurations, authority predecessors, and missingness. Historical resources can help where coverage matches~\cite{rahman2026}; a declared version range is not an exact installed tree~\cite{npmlock}. A checksum cannot replace missing source-time evidence.

Compare random, metadata, reach, maintainer-portfolio, and regularized tabular baselines before graph learning. Add workflow and authority evidence separately and include missingness-only ablations. Use chronological evaluation, campaign grouping, package-disjoint sensitivity checks, and validation-only tuning. Report budget-specific precision/recall and PR-AUC against the observed base rate; calibration requires representative prevalence or justified sampling correction. Release predictions and exclusions, including null results. Existing temporal studies supply useful precedents~\cite{supplytgn2026,patchrisk2026}, but the incremental value of these features for documented publisher compromise remains unevaluated here.
