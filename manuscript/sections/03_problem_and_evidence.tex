\section{Data and Graph Construction}
\subsection{Collection and Observation Scope}
Collection starts from a high-impact npm list and follows dependencies through deps.dev. The collector requests registry metadata and looks for \code{.github/workflows} at HEAD in linked GitHub repositories (Fig.~\ref{fig:system}). The retained archive has \StudyPackages{} identifiers, 22,340 version-metadata rows, \StudyMaintainers{} usernames, and 79,405 package--maintainer relations. Its queue dates span June 13--16, 2026, but individual fields lack a common acquisition cutoff. Our October 20 analysis uses the archive's recorded checksum. Among its identifiers, 2,745 encode bundled contexts under deps.dev's representation~\cite{depsdev}. Neither these context nodes nor the seeded expansion constitute a random registry sample.

The data contain 121,885 version-edge rows and 88,113 distinct name adjacencies. We reverse all explicit declaring-to-dependency adjacencies to measure downstream reach. Stored target-node \code{DIRECT}/\code{INDIRECT} labels are relative to a resolution root; filtering by them would not recover global direct adjacencies~\cite{depsdev}.

\subsection{Endpoints and Missing Evidence}
We evaluate three endpoint universes: all package names, packages with any positive workflow observation, and distinct repository keys associated with those positive observations. The \StudyWorkflowPackages{} positive packages map to \StudyWorkflowRepos{} repositories. Keys are case-folded owner/name pairs with a trailing transport \code{.git} removed. Mapping deduplicates repositories without verifying redirects, commits, jobs, or CI installations.

The archive lacks maintainer mappings for 3,081 identifiers and completed workflow flags for 3,772. Moreover, a zero flag can mean either directory absence or repository unavailability. Workflow endpoints therefore require a positive observation. Of the 7,171 such repositories, 7,158 have a reachable maintainer source. We retain 7,171 as the coverage denominator and exclude the 13 source-free repositories from all-source exclusion counts.

\subsection{Two Graph Representations}
The primary graph merges versions sharing a package identifier. A second graph retains 40,806 (package, version) nodes and joins paths only at matching version keys. A maintained package seeds all its retained versions; without a version node, it contributes only its eligible seed endpoint. Both graphs include seeds and use the same positive workflow observations. Version continuity removes some paths formed by merging versions. However, retained contexts and acquisition times are still mixed, so neither graph reconstructs a historical installation.
