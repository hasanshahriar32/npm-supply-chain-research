\section{Data and Graph Construction}
\subsection{Collection and Observation Scope}
Our pipeline seeds an npm high-impact list, expands dependencies through deps.dev, retrieves registry metadata, and checks linked GitHub repositories for a \code{.github/workflows} directory at HEAD (Fig.~\ref{fig:system}). The archive contains \StudyPackages{} identifiers, 22,340 version-metadata rows, \StudyMaintainers{} usernames, and 79,405 package--maintainer relations. Queue insertions span June 13--16, 2026; they do not establish a shared field-acquisition cutoff. We analyze the checksum-retained archive on October 20. Its 2,745 bundled-context identifiers are context-qualified graph nodes, not separate registry coordinates~\cite{depsdev}. This expansion is not a random npm sample.

The data contain 121,885 version-edge rows and 88,113 distinct name adjacencies. We reverse all explicit declaring-to-dependency adjacencies to measure downstream reach. Stored target-node \code{DIRECT}/\code{INDIRECT} labels are relative to a resolution root; filtering by them would not recover global direct adjacencies~\cite{depsdev}.

\subsection{Endpoints and Missing Evidence}
We evaluate three endpoint universes: all package names, packages with any positive workflow observation, and distinct repository keys associated with those positive observations. The \StudyWorkflowPackages{} positive packages map to \StudyWorkflowRepos{} repositories. Keys are case-folded owner/name pairs with a trailing transport \code{.git} removed. Mapping deduplicates repositories without verifying redirects, commits, jobs, or CI installations.

There are 3,081 packages without an observed maintainer mapping and 3,772 without a completed workflow flag. A stored zero flag can conflate an absent directory with an unavailable repository. We therefore use positive observations for workflow endpoints and do not treat zero or missing values as proof of safety or workflow absence. Of the 7,171 positive repositories, 7,158 are reachable from an observed maintainer portfolio. Coverage percentages use all 7,171; all-source exclusion requires a nonempty observed source set.

\subsection{Two Graph Representations}
Our primary graph collapses retained versions into package-name nodes. For sensitivity analysis, we construct 40,806 exact (package, version) nodes and permit traversal only when adjacent version keys match. Each maintained package seeds every version present in that graph; packages without a version node retain only their eligible seed endpoint. Reach includes maintained seeds, and the same positive endpoint definition is used for both representations. Version continuity can remove paths created by joining incompatible versions, but both graphs combine retained resolution contexts and acquisition times. The version graph is a sensitivity representation, not a historical installation or ground truth.
