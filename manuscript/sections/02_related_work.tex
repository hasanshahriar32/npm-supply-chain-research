\section{Related Work and Novelty Boundary}
\label{sec:related}
\subsection{Ecosystem Structure and Metadata Signals}
Zimmermann et al. analyze npm dependencies, maintainers, and security issues, establishing the importance of concentrated trust~\cite{zimmermann2019}. Zahan et al. investigate metadata weaknesses, including install scripts, inactive maintenance, and expired maintainer email domains~\cite{zahan2022}. These studies preclude claiming maintainer degree or metadata hygiene as new concepts. Our contribution concerns the consistency and interpretation of artifacts used to operationalize those concepts.

\subsection{Payload Detection and Incident Collections}
Ohm et al. compile documented malicious packages and organize supply-chain attack techniques~\cite{ohm2020}. Amalfi combines classifiers, source reproducibility checks, and clone detection~\cite{sejfia2022}. Guo et al.'s updated empirical study compares malicious-package detectors on a unified benchmark~\cite{guo2026}. These tasks evaluate released package content. A package classified as benign in a release corpus is not automatically a non-event control for whether its publisher is compromised in a later horizon. We do not transfer detection performance or labels into a prospective ranking task.

\subsection{Public Workflows and Release Authority}
Koishybayev et al. measure GitHub workflow security properties, while ARGUS analyzes code injection through staged taint analysis~\cite{koishybayev2022,muralee2023}. Workflow-directory presence is therefore a much coarser observation than the existing security analyses. GitHub documentation provides concrete configuration semantics for permissions and privileged triggers~\cite{githubsecure}. Santos-Grueiro's release-authority measurement compares predecessor releases across public authority evidence and reports that its review triggers do not overlap exact malicious versions in the studied cohort~\cite{santos2026}. We consequently treat authority change as a separate review surface, not an established malware predictor.

\subsection{Historical Data and Temporal Forecasting}
npm-follower archives package releases, including material subsequently removed from the live registry~\cite{pinckney2023}. CHRONO-RESOLUTION provides dependency resolution at release points~\cite{rahman2026}. Historical graph construction alone is therefore not a sufficient novelty claim. More directly, SupplyTGN studies cutoff-safe temporal risk ranking in an OSV-seeded PyPI setting~\cite{supplytgn2026}. PatchRisk studies future transitive vulnerability exposure for npm and PyPI using temporal and package-disjoint evaluation~\cite{patchrisk2026}. The latter was published after the repository's August research notes and materially narrows the novelty of a broad ``leakage-aware package forecasting'' claim. Its target concerns future vulnerability advisories, rather than adjudicated publisher compromise.
