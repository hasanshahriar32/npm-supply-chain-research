\section{Introduction}
Dependency graphs distribute both functionality and trust. Prior npm research establishes that dependency concentration, maintainer sharing, and metadata weaknesses create systemic review concerns~\cite{zimmermann2019,zahan2022}. Turning these observations into a defensive ranking requires consistent inputs and an outcome population appropriate to the claim being tested.

We study a research repository whose collector combines npm metadata, dependency edges, public GitHub workflow-directory observations, and advisories. Its implemented score weights maintainer portfolio size and the number of downstream packages associated with public workflows. Project documents propose graph learning, but the available implementation does not train or evaluate that model.

The repository contains compressed CSV and SQLite metric artifacts with the same package population. We find that their plain dependency and maintainer metrics agree, while workflow-derived values differ substantially. A shared repository revision or population count therefore does not guarantee a coherent snapshot. An analysis can reproduce the CSV faithfully yet misdescribe the database stored beside it.

We investigate three questions: \textbf{RQ1}, whether stored metrics reproduce and agree across artifacts; \textbf{RQ2}, how artifact choice, weighting, and boundary ties change a fixed-budget review queue; and \textbf{RQ3}, which prediction claims the incident evidence supports.

The contributions are an independently executed offline metric audit, a quantitative analysis of review-queue drift, and an evidence-based assessment of benchmark readiness. For \PackageCount{} packages, all seven database metric fields reproduce, but workflow reach differs across artifacts for \DBReachPositive{} packages. Their equal-weight top-\ReviewBudget{} queues share only \ScoreQueueIntersection{} entries. The incident companion supplies event records without eligible controls, so the paper reports measurement results and a proposed evaluation protocol rather than predictive accuracy.
